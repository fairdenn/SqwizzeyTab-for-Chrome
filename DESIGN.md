# SqwizzeyTab — Дизайн-правила и токены

Краткий свод правил для нового таба. Vanilla JS/CSS, без сборщика.
`styles.css` — override-война (тысячи `!important`); финальные фиксы кладём
мастер-блоком **в конец файла** с высокой специфичностью (`#id`, двойные
классы `.x.x`). Активное правило искать через CDP `getMatchedStylesForNode`,
не латать вслепую.

---

## 1. Кнопки (.btn)

Базовый `.btn` (styles.css L614) — единый размер для всех вариантов:

| Токен        | Значение |
|--------------|----------|
| height       | `40px`   |
| border-radius| `12px`   |
| padding      | `0 17px` (по умолчанию), `0 18px` в диалогах |
| font-weight  | `800`    |

**Правило:** `.btn.ghost` и `.btn.primary` ВСЕГДА одинаковы по высоте,
`min-width` и паддингам — отличаются только фоном/цветом, не геометрией.

- `.btn.ghost` — `background: rgba(255,255,255,.08)` (тёмная), полупрозрачная.
- `.btn.primary` — акцентная заливка `var(--accent)`.
- В окнах с парой кнопок задаём общий `min-width` обеим (эталон —
  wallpaperAdjustDialog: `min-width:120px; height:40px` обеим → 120×40).

## 2. Вкладки (.page-pill) — вертикальное центрирование текста

- Пилюля: `.page-pill-wrap` 34px высотой, `border-radius:12px`,
  `overflow:hidden`; радиус pill = радиус wrap (иначе на скруглении
  выглядывает подложка — «белые углы» в светлой теме).
- **Оптический центр глифов = центр кнопки.** Текст вкладки («Home» и т.п.)
  центрируется флексом, точная вертикальная подгонка — через
  `transform: translateY(Npx)` на
  `.page-pill-wrap.page-pill-wrap .page-title.page-title.page-title`
  (спец. 0,5,0 — перебивать тем же уровнем ниже по файлу).
- Слова без нижних выносных элементов (Home, Work) центрируются по
  геометрическому центру капителей = оптический центр. Текущее выверенное
  значение — `translateY(0.5px)` (попиксельно: остаток ≈ 0.07px).
- Проверять ТОЛЬКО попиксельным анализом скриншота крупной кнопки
  (HEADFUL, scale ≥ 14), НЕ через bounding-box `getComputedStyle`.

## 3. Скроллбары — тонкие и ВНУТРИ скруглённой рамки

- Тонкие, под тему (мастер-блок L16797):
  - `::-webkit-scrollbar` width/height `9px`;
  - thumb `rgba(255,255,255,.16)`, `border-radius:8px`,
    `border:2px solid transparent` + `background-clip:padding-box`
    (визуальная ширина трека ~5px);
  - light-тема: thumb `rgba(18,24,26,.22)`;
  - `scrollbar-width: thin` (Firefox-совместимость).
- **Скроллбар не должен торчать за `border-radius`.** Если карточка
  скруглена (`.dialog-card`, `border-radius:20px`) и сама скроллится
  (`overflow:auto`), нативный скроллбар рендерится по внешнему краю и в
  углах режет скругление (видно ТОЛЬКО в headful).
  **Правило:** прокрутку переносим с карточки на ВНУТРЕННИЙ контейнер
  `.dialog-scroll` (`overflow-y:auto`, паддинги карточки + `padding-right`),
  а карточку делаем `overflow:hidden` — её радиус чисто обрезает контент
  вместе со скроллбаром. Трек-маргины (`margin-top/bottom:16px`) уводят
  трек от скруглённых углов. Эталон — `#settingsDialog .dialog-scroll`
  (L16850). Любой новый длинный диалог оборачивать так же.

## 4. Нативный `<select>` — ограничение

- Закрытый `<select>` стилизуется (фон, рамка, паддинги, стрелка).
- **Раскрытый список нативного `<select>` браузером НЕ стилизуется** —
  Chrome рисует системный попап вне CSS. Это ограничение платформы.
  Если нужен полностью кастомный дроп — делать собственный
  div-список (как меню пилюль), не нативный select.

## 5. Темы

- Тёмная — дефолт; светлая — `body.light`.
- Поверхности диалогов: тёмная `rgba(9,22,19,.96)`, светлая
  `rgba(255,255,255,.96)`, `backdrop-filter: blur(28px) saturate(145%)`.
- Акцент — `--accent` / `--accent-text` (задаётся пользователем).

## 6. Композит / проверка (КРИТИЧНО)

Скроллбары за рамкой, halo `backdrop-filter`, субпиксельное положение
текста видны ТОЛЬКО в HEADFUL Chrome (без `--headless`). Запуск: без
`--headless`, `--window-position=3200,3200`, свой `--remote-debugging-port`,
свой `--user-data-dir`, `--force-device-scale-factor=1`,
`Page.captureScreenshot` с `captureBeyondViewport:true`.
